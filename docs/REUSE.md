# Reuse Checklist

## Home Filter Aggregation and Caching

Adopts bbingz's [PR #205](https://github.com/peach-mitao/peach/pull/205) at the pinned source commit `bbf5aac8e9562211c324c2019bff35888266df84`, with the license staying this project's AGPL-3.0-or-later. The work filter set is first computed in a separate subquery, and creators, tags and performers are aggregated by the existing relations, keeping de-duplicated counts and tag visibility. When no tag is selected the ineffective `tag_match` is removed, reusing the existing revision cache, same-key lock and cross-connection write invalidation, without rewriting SQLite statistics online or adding an index migration.

The top people and studios `q_tops` reuse the same filtering approach: compute the usable work set separately, then aggregate by entity, keeping representative work selection, seed sampling, continuation pages and the revision cache. The wrong-statistics regression uses a temporary ledger, a cold cache and a new connection, judges call volume by a work-count limit, and checks output equivalence for the default, JAV, watched and combined scopes. The runtime writes no ledger and changes no SQLite statistics or indexes.

## Mixed Media Roots and Model Reading

Library collection reuses `platform.within_root`'s SMB root identity judgment, with local paths keeping the literal ownership comparison, without visiting mount directories per video. STRM is a link file, and its size and promotional name are not junk evidence for a remote video; the junk queue rescores on read, and existing manual decisions and trash records stay as they are.

YuNet and SFace keep the existing model hash verification, and Python reads the model bytes and hands them to OpenCV's ONNX buffer entry, avoiding the restriction of Windows native file reading on non-ASCII paths. No new model copy, dependency or path retry is added. Isolated verification loads a model of the same hash from an ordinary path and from a Chinese path, and runs detection and feature computation with a synthetic array.

## Local People Metadata for Browser Add

`/api/jav-browser/people` reuses the existing dedicated token and browser permission checks, canonical entity associations and the male-performer exclusion criterion. Person names read only the local ledger and discovery metadata snapshots; when querying a single product code it can also carry the performer names from the detail page, matched by the existing `resolve_entity` first by canonical name then by unique alias, trying aliases in parentheses as well, with unmatched ones returning only the name. Avatars find the installed file through the existing `PreviewService.entity_image`, framed by the face records of `avatar_focus` using the zoom and clamping criteria of `frontend/src/card-art/face-frame.ts`; the existing Pillow shrinks it in memory to a 64px JPEG, with no new avatar written to disk and no external site fetched. When the discovery metadata service is not initialized the snapshot is read directly, avoiding initialization resuming external-site tasks. A missing avatar omits the image field, missing person info returns an empty array, and interface failure and normal absence are reported separately. The userscript shows a gray-background initial and not the work cover, with no new dependencies.

## README Star Chart

`scripts/render_star_history.py` generates it itself, using only the standard library and the GitHub CLI, with no new dependencies. The data comes from GitHub's native public Star history: one record per week, where `days` is the day-by-day increase. The script accumulates by day, with the horizontal axis starting on the day of the first Star and ending at generation time; the blank period between repository creation and the first Star is not drawn. The curve uses monotone cubic interpolation (the same as d3 `curveMonotoneX`), draws no dips, and does not exceed the next day's accumulated value. The picture keeps the peach neon outline, gradient fill, linear absolute-value coordinates and light and dark themes. The script does not fabricate missing records, nor treat the historical cumulative increase as a complete net-change ledger of Star cancellations.

Previously [Star Chart](https://github.com/leereilly/star-chart) v0.3 was reused (MIT, pinned commit `e7fa78bdf8f78da6c3feeb3a97b528fd97d62727`). It accumulates only by week and does not use the `days` field, so rises and falls of growth rate within a week are flattened: the over ten thousand Stars in a single week in 2026-10 could only be drawn as one step or one ramp. Adjusting the column count cannot change the time granularity, so it was changed to self-rendering.

The standalone `Star History` workflow generates the SVG daily and keeps the artifact only on the `star-history` branch, without triggering mainline tests or blocking releases. The static SVG publishing idea is from SakuraMedia; its generation script, which is bound by PolyForm Noncommercial, was not copied.

## SMB Media Reading and Writing

Adopts [smbprotocol 1.17.0](https://github.com/jborean93/smbprotocol/tree/v1.17.0) (MIT, Python ≥3.10, upstream tests include Python 3.14 and Windows, macOS, Linux). The pinned transitive versions are in `uv.lock`; the library wheel is about 128 kB, with cryptography, pyspnego and platform authentication dependencies besides. `opensrc path smbprotocol` did not obtain the source, so `_pool.py`, `_io.py`, `open.py` and `connection.py` at the pinned tag were checked instead.

It reuses authentication, protocol messages and parsers, directory paging and offset reads and writes, as well as `SMBFileTransaction`, `set_info` and `FileRenameInformation`/`FileDispositionInformation`/`FileEndOfFileInformation`. Peach keeps fixed-root authorization, absolute request deadlines, cancellation, credential isolation and media sessions; organizing and permanent deletion keep the existing plans, ledger transactions and failure recovery. `stat()` on a directory entry sends extra requests, and scanning consumes the enumerated metadata; the transport imposes a deadline on the library's response events, and on timeout cancels and disconnects the exclusive connection. SDK authentication logs stay at WARNING, and DFS and reparse points are rejected. Writes never overwrite the rename target and never cross declared roots, with write permission judged by the share server; the loopback HTTP for tools stays read-only.

fsspec was not adopted, since its SMB layer is still smbprotocol, which cannot replace media tool input and cancellation; pysmb's SMB1/2 capability does not cover the same SMB3 needs. FFmpeg's native SMB depends on binary builds, and the local tool does not list this protocol, so an HTTP Range loopback bridge is used. Isolated regressions cover authentication, reading, concurrent offsets, configuration and scan pairing; actual FFmpeg extracts frames through the tail index and seek of a synthetic video. Real NAS throughput and compatibility were not obtained, and no real ledger was written.

AMF derives its context from the D3D11 device and recognizes only AMD graphics cards; on a mixed-GPU machine the default index is often another card, so `-init_hw_device d3d11va=peach:N` plus `hwupload` is used to probe by index, and on derivation failure it falls back to software decoding plus AMF. The cross-compilation approach follows `50-amf.sh` and `50-onevpl.sh` of [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds): libvpl's C++ dispatcher needs `libstdc++` when linked statically, and Peach assigns a value to its undefined `CXX_LIB` in CMake so that the generated `vpl.pc` carries this item itself, without rewriting installed files. On 2026-10-23, on a Windows machine with an NVIDIA discrete GPU plus an AMD integrated GPU, process CPU time was measured with gyan FFmpeg 9.0.1 on a 20-second 1080p 10-bit HEVC synthetic clip: pure software decoding 21.9 seconds, D3D11VA decoding 1.6 seconds; libx264 transcoding 62.0 seconds, D3D11VA decoding plus libx264 41.9 seconds; software decoding plus AMF 23.3 seconds, D3D11VA on the AMD index plus AMF 3.4 seconds; CUDA plus NVENC 0.7 seconds. ## Tiered diagnostics

Startup forensics reuses the Python 3.14 standard library's `sys.excepthook`, `threading.excepthook`, `sys.unraisablehook`, `logging.Handler`, `faulthandler`, and `zipfile` (PSF license, no extra install size). `error_reporting` loads before configuration and third-party dependencies, and `support_bundle` collects only selected logs and system fields; Peach keeps the redaction, fallback directory, local permissions, and report-content policy. Optional remote diagnostics reuses the official [sentry-sdk 2.72.0](https://github.com/getsentry/sentry-python/tree/2.72.0) (MIT, maintained, supports Python 3.14); the pinned source was checked with `opensrc path pypi:sentry-sdk`. The SDK handles background HTTP, TLS, the Sentry envelope, and server-side rate limiting; Peach handles local choice, technical-field projection, aggregation of same-kind errors, and a per-machine daily cap. Version statistics and error diagnostics share one default-checked switch, and the SDK is not constructed when it is off; the SDK's global auto-integrations and its tracing, replay, logging, session, and metric collection are all disabled. A narrow override of `HttpTransport._send_envelope` rechecks the local choice version right before sending and strips local transport metadata; it is an internal interface of the pinned version, and upgrades must pass a real SDK envelope regression. An in-memory receiver with no real egress checks the final bytes, queue invalidation after disabling, and that a network outage does not affect local forensics. The only new dependency is `sentry-sdk`, reusing the already declared urllib3 / certifi; size is determined by the release build. A hand-written Sentry protocol or a Workers collection backend was not adopted, to avoid maintaining transport, deduplication, and a viewing UI separately. No real ledger writes.

Fault frequency reuses the pinned `filelock`, `fsutil.atomic_write_text` and the SDK event tags, keeping Peach's consent version, technical projection, cross-process counting and daily batch policy. `diagnostic_frequency` saves bounded technical samples and pending-submission increments, with first, hourly and normal-exit submissions going through the same SDK; turning it off clears the aggregate. Sentry's default event count counts batches and does not automatically sum a custom count tag; the summary is computed by the event's `occurrence_day` and `occurrence_count`. `reporting_transport` reuses the official `HttpTransport`'s `_handle_response`, `_handle_request_error` and queue-drop callbacks, obtaining the HTTP status without reimplementing request, TLS or retry; the fixed internal interfaces are regressed with the real SDK and simulated HTTP. `reporting_delivery` saves only a bounded local receipt; SDK enqueueing, HTTP receipt and receiver retention are interpreted separately. Purpose, environment and public build number reuse Sentry native fields, and tests intercept outbound sending at the same transport boundary. SDK metrics were not turned on and no collection service added: a separate metrics channel would add consent boundaries, quotas and delivery definitions. The count covers only filtered technical faults; for sending and retention limits see [diagnostic verification](DIAGNOSTICS.md). No new Python dependency or real ledger write.

Windows connection cleanup reuses the [Proactor object protocol in CPython 3.14.7](https://github.com/python/cpython/blob/v3.14.7/Lib/asyncio/proactor_events.py) (PSF license, no new dependency). It precisely identifies `WinError 10054` in the pure-standard-library cleanup callback and only completes the socket close, server deregistration, and closed state, without notifying the protocol again and without globally modifying standard-library classes or replacing the event loop. It uses the private interfaces `_sock`, `_server._detach`, and `_called_connection_lost`, which must be re-verified when Python is upgraded. ## Resource indexer

`resource_search.py` uses `parse_capabilities` and `parse_torznab` of Torznab 0.2.1 (MIT, Python ≥3.10, supports the project's Python 3.14). The source is pinned to tag v0.2.1, and the project is still labeled Alpha; an offline XML POC covers caps, GUID magnets, size, seeders, peers, and duplicate tags. The PyPI package adds one direct dependency, with requests already a transitive dependency; acceptance against a real indexer needs a user-configured endpoint.

Requests reuse HTTPX 0.28.1. The SDK's own requests layer has no response-size limit and its exceptions may carry the full URL, so only its parsers are used. Peach handles the two requests per source (caps and search), at most six torrents, a 2 MiB response cap, at most four sources per round, a 45-second budget, disabled redirects, redacted errors, rejection of XML entity declarations, and size, seeder, blacklist, quality ranking, and at most five candidates. Title codes reuse `feeds.scan_code`, and identity and Chinese-subtitle and uncensored edition detection reuse `catalog_rules`. Credentials reuse `CredentialStore` with no cross-machine sync field registered; changing the endpoint does not carry over a saved API key.

It was checked against the [Torznab 1.3 specification](https://torznab.github.io/spec-1.3-draft/torznab/Specification-v1.3.html) and the FC2 query, magnet-field fallback, and partial-failure boundaries of SakuraMedia `torznab.py` (GPL-3.0, revision `9c6a31915c9a364c9d6717798575daf9445916bd`). SakuraMedia is coupled to its ORM and is not a runtime dependency. Candidates are filled into the magnet box of the cloud-download popover, and after user confirmation go through `submit_offline_download`.

OneJAV and Free JAV Torrent give only torrent links. Such entries fetch the torrent through the download proxy of the same origin as the indexer, decoded by bencode2 0.3.35 (MIT, Python ≥3.10, with a cp314 Windows wheel and a pure-Python wheel), and then the SHA-1 of the info dictionary is computed. Evidence: the hash computed from a real sukebei torrent matches the Torznab `infohash`; the Prowlarr proxy returns `application/x-bittorrent` for OneJAV and Free JAV Torrent. Both bencode2 and fastbencode 0.3.11 (Apache-2.0) reject dictionaries with out-of-order keys, so re-encoding gives back the original. bencode2 was chosen because it has a pure-Python fallback. torf (GPL-3.0) does far more than needed, and bencode.py (BitTorrent license) and bencodepy (no updates since 2015) are not adopted.

## Reuse decision gate

Every decision of "use something ready-made or write it ourselves" follows these four rules; the remaining entries in this section are concrete decisions made by them:

- First run a no-write POC on real input, then choose one of "direct dependency, pinned-source implementation, or keep in-house".
- An adopted item must record the pinned version, license, first consumer, and the domain boundary Peach keeps; a candidate dependency must not sit idle.
- Keeping in-house must record the rejected candidates and the irreplaceable constraint, not just "special requirements".
- When an external project is unsuitable as a runtime dependency but its public data model or algorithm is clearly more mature, pin a revision and use it as a reference
  implementation; when the license does not allow derivation or the source is unstable, use it only as behavior evidence and do not copy code.

- Python install and build use [uv](https://github.com/astral-sh/uv) (MIT/Apache-2.0; `pyproject.toml` sets only the lower bound `>=0.12.13` and it does not enter the dependency graph) and the official setup-uv (MIT; version in the [test workflow](../.github/workflows/test.yml)): the uv project interface, `uv.lock`, `uv sync --locked`, and Dependabot using the official `uv` ecosystem. Development and builds create the environment in an isolated worktree, and the production venv does not take part in exact sync; direct dependencies are pinned exactly and transitive dependencies are reproduced by the lock file.
  The test database reuses `tests/support/ledger.py`: migrations generate a template and then copy independent temporary databases ([timing](SOURCING.md)), real migration tests still run migrations; retry tests use the existing sleeper injection point. CI uses independent GitHub Actions runner shards and the existing unittest entry point, Peach maintains only the impact-domain policy, and no concurrent test framework is introduced (see `TESTING.md`).
- Access passwords reuse Python 3.14's [hashlib.scrypt](https://docs.python.org/3.14/library/hashlib.html) and OpenSSL, browser sessions reuse [ItsDangerous](https://itsdangerous.palletsprojects.com/en/stable/) (Pallets, BSD-3-Clause, pure Python, 16 KB wheel, no transitive dependencies), and local atomic configuration writes use tempfile/os.replace and filelock; the access passphrase of the authentication entry, the three rejection responses, and the local configuration guard continue to be reused as before. A release directory must have an active physical main feature with the same name as the directory, at least 20 minutes and at least 120 MiB; an attachment must have a valid measurement, not exceed 30 seconds and 32 MiB, with the main feature at least 40 times the attachment's duration and 10 times its size. Structural evidence counts only with at least 3 such attachments in the same directory, or attachments with the same size, millisecond duration and valid resolution spread over at least 3 release directories. Real creator ownership, own product codes, parts, standalone short animations and ordinary mixed directories are protected; a code inherited from the directory cannot prove an attachment's identity. Structural evidence is enough only for review, and short, small or same-measurement alone cannot prove an ad, and the default auto-quarantine line does not accept candidates whose score is made up only of this evidence. Queries read only the ledger, do not read cloud drive media, and add no dependency.

File names carrying site watermarks first have their own product code and part marker checked, with explicit parts excluded from the junk queue; "bracketed source site name + serial number" videos count only as review evidence, to avoid treating a short clip's packaging watermark as an ad. On-screen forensics can reuse the existing FFmpeg frame extraction and `scripts/windows_ocr.ps1`; local review uses cached thumbnails first. The existing `opencv-python-headless==5.0.0.93` (Apache-2.0, optional vision group) provides [QRCodeDetector](https://docs.opencv.org/4.7.0/de/dc3/classcv_1_1QRCodeDetector.html), which can only locate or decode QR codes and cannot prove a whole film is an ad; the [Windows OcrEngine](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.trycreatefromlanguage) depends on Windows and installed recognition languages. Neither is put on the synchronous scoring path of list requests, so that platform dependencies, image reading and text recognition failures do not affect the review queue; content conclusions are written into per-file review artifacts outside the repository.

Ordinary work images and `images.rar` are kept. Deleting small files over CloudDrive WebDAV reuses the native `Path.unlink`: when a same-directory quarantine rename reports WinError 50, files up to 1 MiB are first fully backed up to `generated/purge-staging/` with the standard-library `shutil.copyfile`, recording the original path, size, and SHA256, and then deleted. If the database fails the backup is restored, and retired after commit; large files continue to report a block. This path adds no dependency, and backup and restore are managed only by `purge_assets`.

English media filename tokenization reuses `wordninja-enhanced==3.2.0` (MIT, released 2026-09-04, Python ≥3.9, pure Python, 11.4 MB wheel, no transitive dependencies). The source was read through `opensrc path pypi:wordninja-enhanced@3.2.0`; the original wordninja is older in release, and the enhanced version offers punctuation preservation and a supplementable dictionary. `space_media_names.py` first produces a per-file review CSV, inserts only spaces, keeps ordinals, characters, and extensions, and infers no person or provenance; real files in the specified directory are verified and then reuse `organize.apply_plan`, the SQLite backup, and the rollback log. Domain vocabulary is in `english_filename_words.txt` (pinned with extra weight, entries should be few: each extra entry lowers high-frequency words such as `a` and `of`), and concatenated strings often mistaken for words are moved out of the word-frequency table in `english_filename_nonwords.txt`. Apostrophe contractions, all-caps abbreviations, domains and site numbers, and hexadecimal viewkeys are not split; Cyrillic look-alike letters count as Latin letters for split points while the original characters are kept. Executed batches use `--recompute-batch <log>` to recompute the review CSV by original names and then go through `--apply --review-csv`.

Junk quarantine on the A drive uses the short name `peach-purge-<32-digit UUID>.peach-quarantine`, and the scan entry skips only this exact format; ordinary media and other `.tmp` files still need review. Quarantine restore and the full local backup keep the transaction boundary of `purge_assets`.

Original-file forensics for A-drive promotional attachments reuses CloudDrive's official `GetDownloadUrlPath` local original-file proxy, without going through Peach transcoding and without passing authentication to other sources; the actual QR-code copies and video forensic frames are in the library review output.

Keeping in-house is not a permanent exemption: when constraints change or candidate implementations are updated, rerun the POC, and this table's conclusions are not a reason to skip an external search.

## Source Text Quality and Lifecycle Repair

The Unicode replacement character `U+FFFD` in source text means information was already lost at decoding. Field extraction, existing candidate selection and final writing share this criterion; a field containing a bad value takes no part in source priority settlement, and the raw snapshot is kept. Normal fields and normal Chinese, Japanese and accented letters are unaffected, and no heuristic transcoding is used to guess the original back.

Existing-text repair reuses field ownership, source identity checks, candidate settlement and the backup, transaction and receipt of `UpgradeRepairs`. Only machine-owned corrupted scalar fields can be restored from a normal source of the same product code; person canonical names and manual judgments are kept for review. Catalog repairs already registered as completed are not replayed with the text rule; old task scopes and queues continue to be kept. Assets awaiting re-collection use a standalone text rule identity, previously completed upgrade tasks do not swallow the new repair, and tasks still running or already cancelled by the user keep their original state.

The playback lifecycle reuses `e41222e312443b5d0fc7be87d2f7eca9c1d61055` of [PR190](https://github.com/peach-mitao/peach/pull/190): shared segments are counted by consumer, generation is cancelled only when the last consumer leaves, and the subprocess is waited for to be reclaimed; file responses keep outer cancellation and runtime errors. Image and database work of avatar confirmation share the worker thread, and installation is locked per entity. The current ASGI response header middleware, SMB input and image preprocessing keep Peach's mainline implementation; the UI, dependency and test scheduling changes of that PR were not adopted.

Anonymous signature verification reuses the sole entry, timestamp expression and string constraints of [PR150](https://github.com/peach-mitao/peach/pull/150), adapting to the existing dynamic variable resolution interface. Media responses reuse the passive type verification, CSP `sandbox` and `nosniff` of [PR131](https://github.com/peach-mitao/peach/pull/131); HLS manifests remain readable, and old active-document caches do not hit. All of the above use the existing standard library, Starlette and filelock, with no new dependency.

## Local Extra Media Recognition

Extra media recognition reuses `catalog_rules.local_extra_type`, `is_local_extra` and the existing `scan.is_sidecar`, compatible with the explicit file markers and dedicated directories of Plex, Kodi, Emby and Jellyfin. For the rule sources, full markers and boundaries see [extra media naming evidence](reference-snapshots/local-trailer-evidence.md).

The classification model and trailing digit handling refer to Jellyfin's `Emby.Naming`, at the pinned commit [`c7ce6a1b56ee7dcc1896250df0f2f9deaa828a81`](https://github.com/jellyfin/jellyfin/tree/c7ce6a1b56ee7dcc1896250df0f2f9deaa828a81/Emby.Naming), a continuously maintained media server project; the module declares GPL-3.0-only, targets .NET 10, and depends on `MediaBrowser.Common` and `MediaBrowser.Model`. The rules and parsing implementation were read through opensrc, and the three cached files were checked byte for byte against the original upstream files at the pinned commit. Peach refers to the rule facts and parsing boundaries, implementing its own policy with the Python 3.14 standard library `pathlib`, string operations and `functools`, without copying upstream source files or introducing a .NET service, runtime or media server dependency; no new Python dependency or install size was added.

The same classifier is used for scanning, push discovery, first-run pre-check, background probing, metadata collection, library lists, version groups, entity counts and inventory statistics. Dedicated directories support nesting, with paths truncated at the longest declared media library root; even if the media library root itself is called `Shorts` or `Extras`, ordinary videos inside it are not treated as extras directories. Explicit file name markers take effect as usual; nothing is inferred from duration, resolution or words in the middle of a title. Old records are excluded in ordinary library and background workloads, while single-item details, media, ratings and playback history are kept; no migration or cleanup of the real ledger is added. Temporary directory and ledger regressions cover the four vendors' naming, numbering, nested directories, library root protection, cross-platform paths and read-only behavior.

## Media Reading and Per-Item Timeouts

`media_io` reuses the short-lived subprocess approach of `local_poster` and the standard library [`subprocess.run(timeout=…)`](https://docs.python.org/3.14/library/subprocess.html#subprocess.run). Directory enumeration, NFO, image references, path resolution and file attributes are obtained in a read-only subprocess; after a timeout the process is first terminated and reclaimed, and then the next item is handled. NFO parsing and image reference boundaries are still maintained by `library_nfo`, and scanning continues to use the batch registration and checkpoints of `scan_location`. The task layer caches directories that failed in this run, avoiding waiting on the same fault video by video.

Preview generation reuses `frame_capture` and `processing_control.deadline_after`, with frame extraction and tiling for the same video sharing a deadline; user pause does not use the activity budget. Failures to save public state, evidence and artifacts propagate to the task layer, and only media reading or source forensics failures enter the per-item issue list. Tests cover timed-out process reclamation, adjacent directories continuing, product code retention after NFO failure, the total preview time limit and interruption of public writes. The standard library is maintained with the Python runtime, PSF license, supporting Windows/macOS/Linux, with no new dependency.

## Media Library and Root Directory Identity

Identity generation reuses UUIDv4 and UUIDv5 of the Python 3.14 standard library [`uuid`](https://docs.python.org/3.14/library/uuid.html) (PSF license, maintained with the runtime, Windows/macOS/Linux, no new install size); path ownership reuses `platform.resolve_root` and `PureWindowsPath`, configuration writing reuses `fsutil.atomic_write_text`, and scanning keeps the SQLite upsert and existing checkpoints. The media library grouping, directory index, source probing and download channels in the current tree and in Git jointly consume these identities.

The ownership of media libraries and root directories is Peach's domain model, and standalone media servers such as Jellyfin/Emby or database ORMs are not introduced: these options cannot directly maintain the existing ledger, personal records and the Windows ledger path contract. Reading old configuration uses a deterministic upgrade, and explicit saving persists identities; the random UUID of a new entity is unrelated to the display name. Isolated cases cover configuration round trip, same-named libraries, reordering, relocation, root directories offline and protection of scan personal records; for the implementation and acceptance boundaries see [ADR-0115](adr/0115-library-and-storage-root-identity.md). No new dependency, and the real ledger is not written automatically.


## Browser Brand Icons and Local File Identity

The browser marks on the taste page use local static assets and request no brand websites at display time. The generic icons come from [browser-logos](https://github.com/alrra/browser-logos/tree/58881b84c4d73adc03c06fa2c275a7abee02d935), with the pinned revision `58881b84c4d73adc03c06fa2c275a7abee02d935`; brand trademarks belong to their original holders. The sources, digests, types and aliases of the other brands are recorded in `resources/browser-icons/manifest.json`. 115 uses the `IDR_MAINFRAME` main icon of the installed browser's PE, without loading or executing the program; a website mark cannot replace the app icon. Unknown brands keep using the generic icon, and are not passed off as Chrome by the Chromium engine.

Local discovery keeps reusing `watchdog` native file events. When configuration is missing local directory monitoring is on, with explicit off kept; cloud drive mounts are not subscribed recursively. An empty queue waits for events, with no periodic directory traversal added. Local move events carry the old path, and accumulated system file identities are used to keep IDs across same-volume renames and moves; standard library file attributes and `FileLock` with atomic writes carry the private cache, adding no hash traversal or media reading. Cross-volume copies and files whose old path still exists are not merged automatically. Files with no identity record before an upgrade that moved while the service was down still need full-library maintenance or manual confirmation, and cannot be reattached by size and file name alone.
