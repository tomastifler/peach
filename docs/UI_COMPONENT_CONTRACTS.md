# UI Component Contracts

This file maintains component choice and interaction constraints; for the execution flow see the [UI skill](../.claude/skills/peach-web-ui/SKILL.md), and for hierarchy and layout principles the [design guidelines](DESIGN_GUIDELINES.md). Read the relevant sections for the current task.

## Applicable Component Systems

React and BoardUI components, colors and sizes follow [BoardUI adaptation](BOARD_UI.md) and ADR-0031, keeping the established blue primary action and the original component constraints. The legacy Geist `--ink`, `--ground`, `--tungsten` and DOM classes constrain only existing controls that use this vocabulary, and do not override BoardUI tokens.

The Switch, Toggle and DOM helper names in the table below must be understood in context of their system: BoardUI Switch is a boolean input, while the legacy Switch is a radio segmented control. When modifying an existing control, reuse its implementation, and do not rewrite another system just to satisfy old naming rules. For values, media ratios and framing, the current implementation and its tests govern.

## Component Choice

| Need | Use | Do not use |
| --- | --- | --- |
| Persistent feedback beside fields, cards and sections | Note | Toast, empty state |
| Page/system-level problems and recovery actions | Banner | Note |
| Brief action receipt | Toast | Persistent Note |
| Confirmation before a write | `confirmModal()` | Native `confirm()`, Toast |
| One primary action plus 1–4 close variants | Split Button (primary action on the left, the first menu item having the same name and doing the same thing) | Flattening variants into side-by-side buttons, using a destructive action as the primary action |
| Reordering within a row | `wireDragReorder()` drag | Up/down move buttons |
| Progress state with a known total | Progress | Decorative blue bar |
| A user-triggered action waiting for a result | Spinner | Spinning the original action icon, Loading Dots |
| A background task still advancing | Loading Dots | Spinner, fake percentages |
| First wait for the content structure of a whole page or large block | Skeleton | Spinner, Loading Dots |
| 2–3 mutually exclusive views | Legacy Switch (radio) or an existing segmented component | Toggle |
| Boolean switch | Legacy Toggle or BoardUI Switch | Radio segmented control |
| Menu without layout height change | Menu/Listbox; open and close go through `presentMenu`/`dismissMenu`, with the motion only in the one copy at the Board layer | Collapse animation, writing another 150ms of your own |
| Input with search semantics | Search Input (search icon prefix; swap in a Spinner in place while searching) | Bare input without icon |
| Fullscreen command/settings overlay | Dialog motion with locking evidence | Applying the same animation to ordinary menus |
| Expanding body text or groups | Collapse | Self-made easing |
| A group of inputs/candidates and their bottom actions | Fieldset | Self-made card Footer |
| Overflowing content in a fixed-height area | Scroller | Page-level scrolling or nested scroll areas |
| No data or results | Empty State (icon, title and description in one group) | Bare gray text or splitting the description outside the component |
| Icon meaning and supplementary notes | Tooltip | Letting a popover widen the page |

## Components and Visuals

- React pages first extend existing BoardUI composites; legacy DOM pages reuse `frontend/src/ui-kit/`, and do not copy one-off classes and templates for the same semantics.
- Data tables that need full-set sorting, paging, cross-page selection and bulk actions reuse TanStack Table, BoardUI Table, `DataTableFrame` and `SelectionDock`; a few static relations keep the existing simple tables, with no paging and selection forced on them. Default page size and selection scope follow the actual page contract.
- The title of a single-panel section on management pages goes inside the panel, not repeated outside the frame; multi-card groups may use titles outside the frame. Sibling section titles use `text-title-2-medium`, and the loading and content states share weight 500, 20px size and 26px line height.
- Control heights take only the four tiers `--control-h-inline`/`-compact`/`--control-h`/`-large`, and controls of the same kind in one row share a tier; icons on the same line as text use `--icon-inline`, and standalone icons take a fixed value by control tier; a dropdown must show what it selects even without opening (choose one of: label above, trigger prefix, or the popover title of a grid picker). For criteria and bad examples see sections 2, 10 and 11 of `docs/DESIGN_GUIDELINES.md`.
- React uses BoardUI semantic tokens, and legacy styles use the corresponding `:root` tokens; a new token must explain what semantics the existing vocabulary cannot express.
- Imageless avatars, initials and default portraits reuse the [BoardUI imageless avatar spec](BOARD_UI.md#imageless-avatars-and-floating-card-subpages), while also checking the carrying surface's light and dark themes, hover and selected states; data not obtained must not be treated as a disabled action to lower the foreground contrast. Tables, forms and floating cards use the full type scale and the matching spacing, and reused snapshots must include Peach's registered dark-mode exceptions.
- Font weights have only three tiers, 400/500/600, and titles choose medium or semibold by the established hierarchy; radii use only `--badge-radius`/`--control-radius`/`--surface-radius`/`--floating-radius`/`--pill-radius` plus `50%` and `0`, and header and footer strips inside bordered containers use `calc(… - 1px)` to stay concentric. Literal values for both are rejected by `tests/test_web_ui.py`, and the ownership criteria are in the `:root` comments.
- The legacy Geist layer is monochrome first: `--tungsten` goes only to focus rings, links, progress/data and the Toggle on state. A primary action uses `--ink` background with `--ground` text, at most one per screen. A title's hover underline does not turn blue, and count badges are neutral gray. Other selectors referencing `--tungsten` are rejected by `tests/test_web_ui.py`; for measurements see "Selected state and switch colors" and "All Button variants and states" in `vercel-geist-semantics-measured.md`.
- A selected state is fill only: always an `--hover` background with `--ink` text, with no border, no `inset` ring line and no font weight (the Geist Switch/Tabs class names have none of the three). Since fill is reserved for selection, on **the same horizontal row** the hover of an unselected mutually exclusive option only raises the text color to `--ink`; buttons without a selected state and isolated switches without side-by-side neighbors still raise the fill on hover as before. Sidebar navigation (`.edge`/`.dnav`) divides the work the opposite way: measurement shows the Geist left column raises the fill on hover and the current item holds the text and icon color, so do not extend the horizontal-row rule to it. For the checklist see "Selected state and its hover" and "Sidebar navigation is the exception" in the same snapshot.
- Button hover only raises the fill: secondary goes to `color-mix(in srgb,var(--ink) 8%,var(--ground))` (the Geist gray-200 tier, one value site-wide), primary to `color-mix(in srgb,var(--ink) 88%,var(--ground))`, and neither border nor text color moves. The primary hover rule must write `color:var(--ground)` itself, otherwise the `color:var(--ink)` in the wider generic hover of the same group has no competitor and lands as white text on a white solid light background. Disabled uses the `--surface` background, `--border-15` border and `--muted` text, not `opacity`; no `scale` on press. All three are backed by the Geist Button source rules.
- `outline:0`/`outline:none` is allowed only where the same rule gives a replacement focus style (`box-shadow` or a child element outline), or where an input's focus is taken over by a container with `:focus-within`; reduced motion is turned off uniformly by the global `@media (prefers-reduced-motion:reduce)`, not patched place by place.
- The hover state of a dangerous action is always an `--drop` solid fill with white text. With only a red border and red text, the resting and hover states look almost equally bright on a dark background, and you cannot tell it is irreversible before pressing; text destructive buttons use one form site-wide, and icon-only delete keys do not apply. Geist's error Button is likewise a solid red fill, only it is red at rest already. For measurements see `vercel-geist-controls-measured.md`.
- A button's leading icon appears only when the icon points at an object (source site, current selection, platform) or a direction of form (the `chevron-down` on the right of a trigger); when the text already says the verb, none is added, since a redundant glyph such as `+ Add`, `↻ Refresh` or `✓ Save` flattens the visual weight of primary and secondary actions on the same row. An icon key must have an `aria-label` whose name states the action and object rather than describing the icon's shape. For the criteria and the Geist Button documentation text see `docs/reference-snapshots/vercel-geist-button-icons.md`; the official Geist icon SVGs have no direct way to fetch them, and the same snapshot records why.
- An input and a button on the same row share `--control-h` and do not each write a pixel number: two controls 3px apart are no longer one row, and the difference usually comes from the narrow-screen anti-zoom rule raising only one of them.
- A glyph stands for only one meaning, and one meaning has only one glyph. To pick a glyph, first ask which noun or direction it refers to: `file-*` for file types, `hard-drive` for local, `rss` for subscription feeds, `chevron-down` for taking another page below, `shuffle` for swapping a batch in place, and `refresh-cw` belongs only to "ask the source whether there are updates"; no filter results and a comparison finding nothing are two empty states and cannot share one glyph. Icon semantics are reviewed together with the control's accessible name and the actual operation. Symbols with no users are deleted together from the list in `scripts/vendor_web_dependencies.mjs` and from the sprite, and spares the user explicitly named to keep are explained next to the list.
- No motion may be added without direct evidence. The evidence for menu open/close is boardui `menu-styles.ts` (`docs/BOARD_UI.md`), already in board.css's shared rules; the old Geist layer still has no animation.
- The UI prefers showing readouts, current state and executable actions, and omits implementation details that do not help decisions. Costs, estimation limits, privacy upload consent and the scope of irreversible operations must be kept; units follow numbers, and necessary definitions go in an appropriate help entry.

## Waiting and Receipts

- Progress must have a real `value/max`, visible units and `aria-valuemin/max/now`; the divider goes after the complete metric (including the progress bar).
- Spinner gives feedback only for actions the user directly triggers, and the trigger always calls `setActionBusy()`: it writes `aria-busy=true` and `aria-disabled=true`, grays out visually, blocks repeat triggers, and stays focusable; during the request wait, native `disabled` must not be used, and is kept only for states where the action truly cannot run, such as missing input or no permission. Background fetches of unknown duration use Loading Dots. First data fetch of a whole page or large block uses Skeleton to reserve the final structure. Spinner/Loading Dots keep visible status text; Skeleton keeps only a status name for assistive technology and draws no separate "Loading" copy. All three respect reduced motion.
- A user write operation calls the shared `actionReceipt()` to send one past-tense Toast only after the server's final success; a state that can be fully restored by a safe inverse operation offers an 8-second "Undo", while permanent deletion, credentials, saving to the ledger and the like do not fake an undo. Merely opening a panel/menu/Dialog does not count as completing an operation and sends no Toast; on failure, besides a short Toast, the reason and the retry entry stay in place.
- One page entry presents only one waiting state; deep-link startup and page data fetching reuse the same Skeleton, and a Spinner switching to Loading Dots or Skeleton is forbidden.
- A Skeleton covers only the content area that is truly waiting; static titles, navigation and filter controls that can be obtained synchronously show immediately. The skeleton must reuse the final container's width, column count and alignment: a card grid spans horizontally, a centered panel stays centered, and a single generic placeholder column must not replace the structures of different pages.
- Placeholders inside a skeleton accept no pointer and have no hover feedback at all (turned off in one place in `09-skeleton.css`); a key that can run only after data arrives uses native `disabled` plus `data-skeleton-action`, showing the site-wide shared disabled surface (`--surface` background, `--border-15` ring, `--muted` text, not-allowed), without opacity, and without pretending to be a clickable final tier.
- The end of paging, empty pages and "No more content" are neutral terminal states and use a dismissible Note; only faults that need recovery or handling may enter a red error Note.
- The result of the last finished run is not shown by default. It is a snapshot of that moment, and spreading it out on entering the page would be read as the present state, with nothing on the page saying it is old; only tasks still in progress automatically take over the page.
- An Empty State's title and description must sit inside the component together; a full-page empty state keeps a uniform 16px from the toolbar above, and must not be wrapped in another empty card.

## Forms and Popovers

- Legacy Switch segmented controls share a radio `name`, start with one `checked`, and support the keyboard; boolean state uses the boolean control of the corresponding system, and BoardUI Switch does not adopt the radio contract.
- Each menu item contains the same icon and text as the entry, the menu scrolls internally with `overscroll-behavior:contain`, and must not make the browser page grow a scrollbar. Anchored menus always go through `wireAnchoredMenu`: the height is pressed to the space truly left on the trigger's side (the top edge is the lower edge of the `--topH` top bar), and if it does not fit, it scrolls within the menu and does not straddle the trigger; page scrolling closes the menu, and the menu's own scrolling does not.
- Read-only queries (search, filter) get no submit button: Enter executes, and the busy state lands on the form itself (`form[aria-busy]` plus the prefix swapped in place for a Spinner). A submission with side effects must have a button, and Enter must be able to submit as well. When the form has other fields besides this input, the browser does no implicit submission, so Enter must take over `requestSubmit()` itself and skip `isComposing`. For criteria and measurements see `docs/reference-snapshots/vercel-forms-submit-affordance.md`.
- Confirmation popovers always go through `confirmModal()`: carried by a native `<dialog>`, the title is a declarative sentence, the body first states the consequence and names
  the two values involved, the primary button is a "verb + noun" with the same verb as the title, the cancel key just says "Cancel", and the success Toast
  matches the primary button's verb one to one. The write is handed to `onConfirm`, the busy state lands on the primary button, and on failure the popover does not close and the reason stays below the body
  awaiting a retry. For shape and copy criteria see `docs/reference-snapshots/vercel-geist-modal-measured.md`.
- A dropdown's purpose is marked by a 16px prefix icon on the left inside the box, not by hanging a text label on the same row: Geist's text Label is block-level and sits above the control, it has no inline side-by-side form, and a toolbar row has no space above. The accessible name is carried by `aria-label` instead.
- A popover's title bar and scrolling body are layered: the title divider belongs to the card's full width, and the scrollbar belongs only to the body.
- A Fieldset body uses a uniform 20px padding; the title bar and the bottom action bar are both `--fieldset-bar-h` (52px), vertically centered, with 20px left and 16px right. The title goes inside the box, not in a native `<legend>`: it cuts a notch into the top border, and when cards in the same group have different content heights the notch positions also fall out of line. Cards in the same group must have equal height, and changing content goes into only one vertical Scroller.

## Media and Page State

- Follow source tags first obey the type from the source record: only tags explicitly marked `general` may enter cards, the top filter and the online tags page, and `artist`/`character`/`copyright`/`metadata` and unknown types must not be guessed as `general` from word form. Generic-word cleanup is the second gate and handles only `general` already confirmed; the detail can show all source tags, colored by real type.
- The narrow-screen collapse of the player control bar is decided by the player's own width (`ResizeObserver` observing `player.el()`), not by media queries: under the same viewport, the player widths of theater mode and normal view differ greatly, and a viewport criterion would collapse needlessly in theater mode and keep overflowing the frame in normal view. For the threshold and prompt appearance see `youtube-player-controls-user-screenshot.md`.
- Any entry that requests first and then redraws the whole page must be bound to a navigation generation; comparing only `location.pathname` cannot stop an old response for "leaving and quickly returning to the same path".
